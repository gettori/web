Tori ships with a set of packs already in place, so a fresh install can open
common projects and start the main agents without a trip to the catalog.

## What ships inside Tori

<BundledTable />

Bundled packs are ordinary catalog packs. Each release embeds gettori/packs
at one commit, and each pack has a page in the [catalog](/packs/) with its
contributor, license and the version it was verified against.

## How it updates

A pack is bundled when Tori needs it itself: the app ships the program it
starts, a fresh install depends on it, or Tori's own repository is built with
it. Everything else is in the catalog, and Tori
[offers the one a file needs](/docs/packs/installing/#packs-tori-offers-on-its-own).

Bundled packs update with Tori. A release carries the bundled set as
gettori/packs had it when the release was cut, and a newer file in the
catalog waits for the next release.

## Switching a bundled pack off

<Steps>

1. Open Settings (the gear in the title bar).

2. Go to the pack's pane: **LSP**, **Linters**, **Debuggers**,
   **Formatters** or **Agents**.

3. Turn off the switch on the pack's card. Tori stops starting it, and you
   can turn it back on there. Themes have no switch: pick another one in
   **Appearance** > **Theme**.

</Steps>

<Aside type="note" title="Replacing a bundled pack">

Copy its file under a new id, change what you need, and switch the bundled
one off. A file in `~/.config/tori/packs/` that reuses a bundled id is
refused, with that fix named, since a file that took over the id would never
receive the bundled pack's updates. Agent files that already carried a bundled id when Tori moved
them into this folder keep it as recorded overrides.

</Aside>
