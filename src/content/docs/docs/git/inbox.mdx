The Inbox lists the sessions whose work is waiting for you to read it, across
every space, with the riskiest at the top. It answers "what do I read first",
not "what finished last".

Open it with the **Inbox** button in the sidebar strip, next to the dock button,
or with `Cmd+Shift+I`. The button shows how many sessions are waiting. Press
`Escape` or **Close** to go back to the workspace.

## What is listed

A session is listed when all of these hold:

- It runs in one of your projects.
- It sent a prompt after you last marked it reviewed.
- Its folder has uncommitted changes, or its branch has commits not pushed yet.
- It changed something since you last marked it reviewed. For a session with
  checkpoints, that means its own files differ. Without checkpoints, it means
  at least one turn edited code.

Once you commit and push the work and the folder is clean, the session drops
off the list by itself, reviewed or not.

The Inbox starts empty. The first time Tori runs with it, everything that
happened before counts as already read, and only new turns show up.

## Reading a row

Each row shows:

- **The score**, on the left. Higher means read it sooner.
- **The session's name**, its folder and its agent.
- **Its last reply**, as a summary of where it stopped.
- **The signals** that make up the score.

Click a row to go to the session. Tori opens the Changes panel on the
**Checkpoints** tab, at the session's first turn you have not reviewed, where
each file opens its diff with [Who wrote this hunk](/docs/git/who-wrote-this/).

## The signals

The score adds up fixed points. Each signal counts once per row, however many
times it happened. The chip shows how many times.

| Signal | Points | What it means |
| --- | --- | --- |
| Secret read | 30 | A turn read or named a secret-shaped file, such as `.env` or a key |
| Checks failed | 25 | The last check a turn ran after its last edit failed |
| Test files deleted | 25 | The session deleted a test file: one in a `test`, `tests`, `__tests__` or `spec` folder, or named like `*.test.*`, `*_test.*` or `test_*` |
| CI, auth or secret file | 20 | The session changed a CI file (`.github/workflows`, `.gitlab-ci.yml` and the like), a file with auth, login, OAuth, credential or permission in its path, or a secret-shaped file |
| Manifest or lockfile | 15 | The session changed a dependency manifest or lockfile, such as `package.json`, `pnpm-lock.yaml`, `Cargo.toml` or `go.sum` |
| Outside the named folders | 15 | The session changed files outside the folders its first prompt or its issue named |
| Shared with another session | 10 | Another session in the same folder also wrote one of these files |
| Edit without reading | 10 | The session changed a file it never looked at first |
| Unverified turn | 10 | A turn changed code and nothing it ran checked it |
| Lines | up to 30 | Lines the session added and removed since you last reviewed it |
| No checkpoints | 0 | Tori has no snapshot to count lines from, so lines and the file signals are missing |

Lines grow slowly: 10 lines are worth about 10 points, 100 about 20, and the
count stops adding at about 1,000. A small change that read a secret file still
ranks above a large clean one.

Only turns after your last review count, so a row that comes back shows the new
work, not the old signals again.

### Outside the named folders

Tori reads the session's first prompt, and the issue its branch was started
from when there is one, for paths: a word with a `/` in it, or a file name with
an extension, whose first part exists in the project. `src/review/mod.rs` names
the `src/review` folder, `README.md` names that file. Every changed file outside
them counts. When nothing in the prompt or the issue looks like a path, this
signal stays off. Tori fetches the issue once per session while it runs.

## Mark reviewed

**Mark reviewed** takes the row off the list until the session starts a new
turn and changes something.

You cannot mark a session that is still working, or one waiting on a question
or an approval: its turn has not finished, and later edits in the same turn
would go unseen. If a new turn starts between the moment you looked and your
click, Tori refuses too and asks you to look again.

<Aside>
Lines are the session's own files, worked out the same way Checkpoints decides
what a turn wrote. Two sessions in one dirty folder are both listed, and a
session that only answered questions can show up next to one that wrote, when
Tori cannot tell who changed a file.
</Aside>

Deleting a session also removes its review mark.
